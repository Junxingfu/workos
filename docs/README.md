## 阅读顺序与维护方式

1. 新任务先读产品与交互，再按任务读取技术设计或运行手册；写代码遵守开发规范。
2. 产品文档决定应当怎样工作；代码和 SQL 是实际实现与字段结构的事实源。发现差异必须修正，不能把实现缺失误写成已经支持。
3. 规则改动直接更新所属文档与对应回归，不再复制一份“新版本 PRD / 补充说明 / 冻结稿”。已明确后置的能力集中在产品文档的范围表。
4. 文档只记录会影响决策的信息。完整 DTO 看 Java/TypeScript，接口看 Controller/Swagger，表结构看 SQL，避免维护多份抄本。
