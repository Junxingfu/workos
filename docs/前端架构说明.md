# WorkOS 前端架构说明

> 适用版本：MVP（PRD V1.3.5）
> 记录日期：2026-09-25
> 目录：`workos-web/`
> 配套文档：启动与部署见 [前端运维手册.md](前端运维手册.md)，接口契约见需求文档 6

## 1. 定位

前端只做三件事：**把事实显示清楚、把决策交回用户、把动作发给后端**。

对应的三条边界：

| 层 | 职责 | 不做什么 |
|---|---|---|
| 前端 | 展示、交互、请求编排 | 不推导业务规则（状态机、逾期判定、等待天数） |
| 后端 | 业务规则唯一事实源 | 不渲染、不返回展示标签 |
| 数据库 | 时间点存 UTC | 不存"今天"这种相对概念 |

MVP 只做 Web 单页应用。不做 SSR、不做 Tauri 桌面壳、不做移动端适配（宽度按桌面 1080px 内容区设计）。

## 2. 技术选型

| 组件 | 版本 | 用途 | 选它的理由 |
|---|---|---|---|
| Vue | ^3.5.13 | 视图框架 | 组合式 API + SFC，单文件同时容纳模板/逻辑/样式，页面级改动不用跳三个文件 |
| Vite | ^6.0.7 | 构建与开发服务器 | 按需编译启动快；dev proxy 直接解决跨域；配置即 `vite.config.ts` |
| TypeScript | ^5.7.2 | 类型 | 后端契约字段多，类型是防拼写错误的最低成本手段 |
| Vue Router | ^4.5.0 | 路由 | 5 个页面按路由懒加载，首屏只加载 Today |
| Pinia | ^2.3.0 | 状态管理 | 已注册备用，**当前没有任何 store**（见 §5.3） |
| Ant Design Vue | ^4.2.6 | UI 组件 | 表单/日期选择/抽屉/时间线开箱可用，避免自造组件拖慢 MVP |
| axios | ^1.7.9 | HTTP | 拦截器统一解包响应与兜底错误 |
| dayjs | ^1.11.13 | 时间 | 体积小、API 与后端 LocalDate/Instant 语义对得上 |

刻意不引入：Element Plus（与 AntD 重复）、Vuex（Pinia 已够）、图表库、Markdown 渲染库（描述字段当前按纯文本展示）、i18n（MVP 只有中文）。

## 3. 运行架构

开发期：

```
浏览器 :5173 ──► Vite Dev Server ──┬── /             → src/**（按需编译，HMR）
                                    └── /api/**       → 反向代理 → Spring Boot :8080
```

生产期：

```
浏览器 :80 ──► Nginx ──┬── /        → dist/（try_files 回落 index.html）
                       └── /api/**  → 反向代理 → Spring Boot :8080
```

两种形态都是**同源**，所以前端代码里没有任何后端地址，`baseURL` 恒为 `/api`。换环境不需要改前端代码，也不需要 `.env`。

## 5. 分层与数据流

### 5.1 单向数据流

```
页面组件
  │  ① 调 api 函数（不直接 axios）
  ▼
src/api/index.ts          接口函数：拼参数、定 URL
  │  ② http.get / http.post
  ▼
src/api/client.ts         axios 拦截器：code !== 0 抛错，否则直接返回 data
  │  ③ 业务数据（已解包）
  ▼
页面组件 ref 状态 ──► 模板渲染 ──► 用户操作 ──► 回到 ①
```

页面拿到的是**已解包的业务数据**，不需要写 `res.data.data`。错误统一抛出 `Error(message)`，页面用 `fail(e)` 提示。

### 5.2 一次典型写操作（以"暂不安排"为例）

```
卡片按钮 → TodayPage.postpone(item)
        → api.updateItem(id, { priority: 'P2' })
        → client 拦截器解包
        → load() 重新拉 GET /api/today
        → 该条从"还没安排"分区消失
```

关键点：**改动后不自己推导结果，重新向后端要一份**。分区归属、计数、排序全部由后端算，前端不做"我以为它该去哪"的判断。

### 5.3 状态管理现状（重要）

Pinia 已在 `main.ts` 注册，但**当前没有任何 store**。原因是这版页面之间没有共享的可变状态：

| 数据 | 当前放法 | 是否该进 Pinia |
|---|---|---|
| 今日分区、收件箱、项目、日报 | 各页面 `ref`，进入页面时拉取 | 不需要——页面间不共享，且每次进来都该拿最新 |
| 抽屉里的事项详情 | `ItemDrawer` 局部状态 | 不需要——单组件树内 |
| 时区等设置 | 后端 `settings` 表在读，前端未缓存 | **需要时再加**：设置会影响全局时间展示，届时建 `useSettingsStore` |

判断标准很简单：**只有一个组件树用到的状态不要进 store**，否则会引入"什么时候刷新 store"的新问题。

## 6. 关键设计决策

### 6.1 用代理，而不是跨域或绝对地址

`baseURL = '/api'` + dev proxy 带来三个好处：代码里没有环境相关地址、开发与生产同源、不需要 `.env` 切换。

代价是一个已踩过的坑：**代理转发时会原样带上 `Origin`**，后端会把它当跨域请求处理。表现为"GET 正常、POST/PUT/DELETE 报 CORS"（GET 不带 `Origin`）。已在两处解决：代理侧移除 `Origin`/`Referer`，后端按 `http://localhost:[*]` 放行任意本地端口。详见 [前端运维手册.md §8](前端运维手册.md)。

### 6.2 不做 mock 层

接口契约（文档 6）已冻结，mock 的价值随契约变动而消失；而 mock 一旦与真实响应结构不一致，会把契约问题藏到联调最后一天。当前所有页面直连真实后端。

### 6.3 id 一律按 string

后端把 `Long` 序列化成字符串（防 JS 精度丢失），所以 `types/index.ts` 里所有 `id` 都是 `string`。**不要 `parseInt`**，也不要用 `===` 和数字比较。

### 6.4 时间：存 UTC，显示按本地

- 传给后端的一律 `.toISOString()`（绝对时间点）
- 纯日期字段（`plannedDate`、`workDate`）传 `'YYYY-MM-DD'`
- 展示用 `dayjs(iso).format(...)`，不做字符串截取
- "今天"由后端按 `settings.timezone` 决定；前端只用 `dayjs()` 做显示与默认值，不承担判定职责

### 6.5 展示与操作分离：ItemCard / ItemDrawer

`ItemCard` 只负责"一眼看懂"：标题、优先级、状态、项目，以及**从字段叠加的次级标签**。`ItemDrawer` 是唯一写入口：改属性、点状态、做跟进、记一句、看历史。

标签由前端叠加而非后端下发是刻意的：接口只返回事实字段，展示文案随时可调而不用改接口。当前最多显示 2 个，顺序为 计划 → 逾期/到期 → 跟进 → 等待 → 剩余步数。

### 6.6 状态变更只走 transitions

前端**从不** `PUT status`。可点的状态按钮直接来自后端返回的 `allowedTransitions`，前端不自己算状态机；类型能力（NOTE 只能 INBOX/DONE/CANCELLED）由后端兜底拒绝。

"在等别人"是例外路径：它不是单纯改状态，还要收 `waitingFor`（必填）、`waitingExpectedAt`、`nextFollowUpAt`，所以点"在等别人"先弹表单再一次性提交。

### 6.7 暂时不做乐观更新

写操作后统一 `load()` 重拉。理由：MVP 阶段正确性优先于几十毫秒观感，且分区归属由后端计算，"先本地改再纠正"容易让同一事项在两个分区闪一下。数据量小、接口都是单表聚合，重拉成本可接受。

### 6.8 日报是"快照 + 确认"两段式

日报页不直接覆盖正文：`/generate` 只写 `generatedContent` 并返回给前端预览，用户点"应用"才调 `/apply-generated` 覆盖正文，且带 `version` 走乐观锁，避免覆盖用户同时编辑的内容。

## 8. 代码约定

1. **SFC 顺序固定**：`<script setup lang="ts">` → `<template>` → `<style scoped>`。
2. **不直接 axios**：所有请求经 `src/api/`。新增接口时同步在 `api/index.ts` 写函数，并在 `types/index.ts` 加类型。
3. **加新导出必须 re-export**：页面从 `@/api` 引入，忘了在 `api/index.ts` re-export 会导致 Vite 编译失败、页面白屏（踩过一次）。
4. **错误提示统一 `fail(e)`**，不要各处写自己的 `message.error` 文案。
5. **样式**：全局变量与通用类在 `styles/main.css`，页面私有样式写在 SFC 的 `scoped` 里。不引入预处理器。
6. **命名**：页面 `XxxPage.vue`、组件 `Xxx.vue`，路由 path 用复数资源名（`/projects`）。

## 10. 扩展指引

### 加一个页面

1. 新增 `src/pages/XxxPage.vue`
2. `src/router/index.ts` 加路由（懒加载）
3. `src/App.vue` 的 `navItems` 加导航项

### 加一个接口

1. `src/types/index.ts` 加响应类型（字段名严格对齐文档 6）
2. `src/api/index.ts` 加函数（路径**不加** `/api` 前缀，`client` 的 `baseURL` 已含）
3. 页面里调用，错误走 `fail(e)`

### 加一个字段

后端加字段后：`types` 补类型 → 需要展示就在 `ItemCard`/`ItemDrawer` 里用。**不要在前端造"计算字段"**（例如自己算逾期天数用于分区判断），那属于后端规则，前端只做展示态文案。

## 11. 技术债与取舍

| 项 | 现状 | 影响 / 何时处理 |
|---|---|---|
| 空脚手架目录 | `stores/ mock/ utils/ pages/*/ components/*/` 共 14 个空目录 | 无声危害，建议删除或明确复用 |
| 无前端测试 | 没有单测/E2E | 契约已冻结、页面少，靠模块编译检查 + 手工验收；页面变多再补 |

| 无分页控件 | 列表一次拉首页数据 | 事项过千后需补分页 |
| 无登录态 | `auth` 未实现，请求不带 token | 上公网前必须补，且后端要同步实现 |
| 描述按纯文本展示 | 未接 Markdown 渲染 | 只提取了"剩余步数"，渲染留待后续 |
| 无深浅色主题 | 固定浅色 | 非 MVP 目标 |

## 12. 视觉与交互规范（design.md）

**`docs/design.md` 是视觉与交互的最高约束**，优先级高于本文件、高于既有实现、高于个人判断：

```
产品需求 > UX 规则 > Design System > Agent 自由发挥
```

实现前必读，实现后按其中的 `VISUAL_REVIEW` 自检。当前实现与规范的对应关系：

| 规范要求 | 落地位置 |
|---|---|
| Sidebar + Main（§12 §13） | `App.vue`，一级导航：今天 / 待整理 / 全部事项 / 项目 / 日报 |
| 颜色与语义色（§4~§6） | `styles/main.css` 的 `:root` 令牌，颜色只在有语义时出现 |
| 字号层级（§7） | `.page-title` 24/600、`.section-title` 16/600、`.item-title` 14/500、`.meta-text` 12/400 |
| 4px 间距与圆角、默认用 border（§8~§10） | 令牌 `--space-*`、`--radius-card: 8px`；列表用 border，阴影只给 Drawer/Modal |
| 用 List 而不是 Card Grid（§16） | `.list` / `.list-row`，五个页面全部使用 |
| ItemCard 三行扫描结构（§17） | `ItemCard.vue`：状态+标题+优先级 / 项目+时间 / 次级标签 |
| 次级标签最多 2 个（§18） | `ItemCard.vue` 的 `labels`，按 等待 → 跟进 → 逾期 → 剩余步数 取前两个 |
| Drawer 是操作中心（§19 §36） | `ItemDrawer.vue` 第一屏：标题 / 项目·优先级·计划日期 / 描述 / 现在要做什么 |
| 等待一次填完（§38） | 点「在等别人」弹轻量表单收齐 等谁+预计+下次跟进，不要求先改状态再保存 |
| 空状态说明原因与下一步（§20） | 各页 `.empty-state` 文案 |
| 禁止项（§3 §2.3 §2.4） | 无渐变、无玻璃拟态、无 KPI 卡片、无大数字统计、无 Emoji、无装饰动画 |

项目详情页刻意不用统计卡片，改为一行事实文本（`待办 / 进行中 / 等待 / 已完成`），符合"禁止巨型 Dashboard Card"。
