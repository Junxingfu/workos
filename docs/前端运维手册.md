
**前端必须先起后端**。Vite 把 `/api` 代理到 `http://localhost:8080`（见 `vite.config.ts`），只起前端时所有接口都会报"无法连接后端服务"。

后端启动方式见 [运维与部署手册.md §2.3](运维与部署手册.md)。

### 2.3 验证

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:5173/        # 期望 200
curl -s http://localhost:5173/api/today | head -c 80                   # 期望 "code":0
```

第二条是关键——它同时验证了前端服务和 `/api` 代理。若返回空或 `Failed to connect to localhost port 8080`，说明后端没起。

再逐个确认页面能编译（首次访问某个路由时 Vite 才会编译该页面，编译失败只在浏览器里暴露）：

```bash
for p in /src/App.vue /src/components/ItemCard.vue /src/components/ItemDrawer.vue \
         /src/pages/TodayPage.vue /src/pages/InboxPage.vue /src/pages/ProjectsPage.vue \
         /src/pages/ProjectDetailPage.vue /src/pages/DailyPage.vue; do
  echo "$(curl -s -o /dev/null -w '%{http_code}' "http://localhost:5173$p")  $p"
done
```

全部 200 即可。

### 2.4 停止

前台运行时 `Ctrl + C`。后台运行时：

```bash
lsof -nP -iTCP:5173 -sTCP:LISTEN     # 找到 PID
kill <PID>
```

**注意**：用 `nohup npm run dev &` 在一次性 shell 会话里启动，进程会随该会话结束被杀掉（实测如此）。要长期驻留请用 `tmux`，或直接用 §5 的静态构建。

## 3. 运行机制

```
浏览器 :5173  ──►  Vite Dev Server
                     ├── /             → src/ 下的 Vue 源码（按需编译）
                     └── /api/**       → 反向代理 → Spring Boot :8080
```

因此开发期**不会触发 CORS**，也不需要在前端配后端地址。后端同时也放行了 `http://localhost:5173`（见后端 `WebMvcConfig`），作为直连时的兜底。

## 4. 配置

| 位置 | 项 | 当前值 | 说明 |
|---|---|---|---|
| `vite.config.ts` | `server.port` | 5173 | 前端端口 |
| `vite.config.ts` | `server.proxy['/api'].target` | `http://localhost:8080` | 后端地址，改后端端口时同步改这里 |
| `vite.config.ts` | `resolve.alias['@']` | `src/` | 源码统一用 `@/` 引入 |
| `src/api/client.ts` | `baseURL` | `/api` | 所有请求走相对路径，靠代理转发 |
| `src/api/client.ts` | `timeout` | 15000ms | 超时时间 |

后端换端口（例如 `SERVER_PORT=9090 mvn spring-boot:run`）时，必须改 `vite.config.ts` 的 `target`，否则代理 502。

## 5. 构建与生产部署

```bash
cd workos-web
npm run build               # 产物在 dist/
npm run preview             # 本地预览 dist/
```

生产推荐：Nginx 托管 `dist/` 并反代 `/api`，前后端同域，不用开 CORS。

```nginx
server {
    listen 80;
    server_name workos.example.com;
    root /var/www/workos/dist;
    index index.html;

    # SPA 路由：刷新 /today、/projects/1 这类路径必须回落到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

部署步骤：

```bash
npm ci                      # 或 npm install
npm run build
rsync -a --delete dist/ user@server:/var/www/workos/dist/
```

注意 `root` 指到 `dist` 的**内容**，不要多一层目录，否则 `try_files` 找不到资源。

## 6. 页面与路由

| 路由 | 页面 | 主要接口 |
|---|---|---|
| `/today` | 今天做什么 / 今天别忘了 / 我在等谁 + 还没安排 | `GET /api/today`、`POST /api/items/{id}/plan`、`PUT /api/items/{id}` |
| `/inbox` | 待整理，含"先都收下" | `GET /api/inbox`、`POST /api/inbox/accept-all` |
| `/projects` | 项目列表与新建 | `GET/POST /api/projects` |
| `/projects/:id` | 项目现状（焦点/进展/卡点/下一步） | `GET /api/projects/{id}`、`PUT /api/projects/{id}/context` |
| `/daily` | 日报：生成 → 预览 → 应用 | `GET/PUT /api/dailies/{date}`、`/generate`、`/apply-generated` |

全局组件：

- 顶栏输入框 = 快速记录，`Alt + Space` 聚焦，回车提交，直接进 Inbox
- 黄色横幅 = 提醒的启动补偿（`GET /api/reminders/pending`），可"稍后 1 小时"或"忽略这次"
- 事项抽屉（`ItemDrawer`）= 打开任一事项卡片后的编辑区：属性修改、状态按钮、到点跟进三选一、"记一句"、历史时间线

| 目录 | 职责 |
|---|---|
| `src/api/` | 全部接口调用，`client.ts` 统一解包与报错 |
| `src/types/` | 与后端契约对应的 TS 类型 |
| `src/pages/` | 5 个页面 |
| `src/components/` | `ItemCard`（卡片 + 待安排决策按钮）、`ItemDrawer` |
| `src/router/` | 路由表 |

## 7. 约定（改动时不要破坏）

1. 所有请求走 `src/api/`，不要在页面里直接 `axios`。响应解包、错误提示统一在 `client.ts`。
2. 页面里报错统一用 `fail(e)`（从 `@/api` 导出），保证提示文案一致。
3. **加新导出时记得在 `src/api/index.ts` 里 re-export**。踩过一次：页面 `import { fail } from '@/api'` 但只从 `client.ts` 导出，Vite 直接编译失败、页面白屏。
4. 后端 `Long` 序列化成字符串，前端 `id` 一律按 `string` 处理，不要 `parseInt`。
5. 时间统一 `dayjs` 处理，传给后端用 `.toISOString()`（UTC 时间点），展示时按本地时区。
6. 状态变更不直接 `PUT status`，只能走 `POST /api/items/{id}/transitions`。
7. "暂不安排" = `PUT /api/items/{id}` + `priority = P2`，不是隐藏。

## 8. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| **GET 正常，但 POST/PUT/DELETE 报 CORS（`Invalid CORS request` 403）** | 代理转发时原样带上了 `Origin`，后端把它当跨域请求；后端只放行了固定端口。GET 不带 `Origin` 所以没事，看起来像"某个接口坏了" | 已修：后端按 `http://localhost:[*]` 放行任意本地端口，且代理侧移除 `Origin`/`Referer`。若再次出现，检查后端 `CORS_ALLOWED_ORIGIN_PATTERNS` |
| 页面白屏，终端刷 `esbuild` 报错 | 页面里引了不存在的导出（例如只从 `client.ts` 导出的函数忘了在 `api/index.ts` re-export） | 看报错里的文件与符号名，补齐导出；Vite 会热更新，改完即恢复 |
| 所有接口报"无法连接后端服务" | 后端没起，或 `proxy.target` 端口不对 | 起后端；`curl localhost:8080/actuator/health` 确认 |
| 接口 404 但后端明明有 | 请求路径少了 `/api` 前缀，或后端没映射 | 前端 `baseURL` 已是 `/api`，页面里写 `/items` 而不是 `/api/items` |
| 刷新 `/projects/1` 出现 404 | Nginx 没配 SPA fallback | 加 `try_files $uri $uri/ /index.html`（见 §5） |
| 启动报端口被占用 | 5173 已被另一个 dev server 占用 | `lsof -nP -iTCP:5173 -sTCP:LISTEN` 找到并 kill，或 `npm run dev -- --port 5174` |
| `npm install` 报 tarball 校验失败 | 依赖目录损坏或网络中断 | `rm -rf node_modules package-lock.json && npm install` |
| 安装很慢 | registry 不是国内源 | `npm config set registry https://registry.npmmirror.com` |
| 日期显示差几小时 | 后端存 UTC 时间点，展示未按本地时区 | 用 `dayjs(iso).format(...)`，不要直接截字符串 |
| 保存后提示"数据已被其他操作修改" | 乐观锁冲突（后端码 1004） | 正常保护，刷新抽屉重新加载最新数据再改 |

日志：dev server 的标准输出就是日志（前台运行时直接看终端；后台运行看 `nohup` 重定向的文件）。浏览器侧问题看 DevTools Console / Network。
