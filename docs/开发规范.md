# 开发规范

本规范替代旧 `docs/archive/` 规范及重复的前端 Agent 长文。当前用户需求优先；业务、交互含义以[产品与交互](产品与交互.md)为准。

## 1. 工程边界

- 先理解业务事实，再调整交互，最后写样式。新增功能必须减少用户维护成本。
- 保持 Vue 3 / TypeScript / Vite / Ant Design Vue 和 Spring Boot / Java 17 / MyBatis-Plus / PostgreSQL。没有真实需要不引入新框架、缓存、消息队列或状态管理层。
- 后端业务写入在 Service，Controller 只处理请求响应，Mapper 管 SQL，Converter 管对象转换。多表写入有事务；失败不能留下半个结果。
- 不复制状态机、Today 归属、逾期、等待天数或业务日计算到前端。
- 前端请求统一经 `api/index.ts → api/client.ts`，失败用 fail；ID 保持字符串，数量可归一化。
- 组件负责展示与交互，公共行为优先提取为 composable；不为减少几行代码创建大量 Base 包装组件。
- Vue SFC 使用 `<script setup lang="ts">`、template、按需 scoped 样式。数据各页面持有，跨页刷新用既有通知机制。
- 状态变化只走 transitions；相同操作全站文案一致。请求携带当前 version，失败时不假装成功。
- 新建表附升级脚本；明确新库和旧库执行方式，不能用重建数据卷代替迁移。

## 2. 交互标准

- 核心动作有可见鼠标入口，快捷键只是加速。行内开始、完成、等待、跟进无需先打开详情。
- 列表显示中文状态；优先级/日期/等待对象可扫描；不只靠颜色表达含义。
- 普通流转不加确认；取消、物理删除、覆盖正文明确后果。进入等待收集必要字段不算多余确认。
- 流转图只突出当前与下一步，按钮依赖 allowedTransitions；不堆所有历史路径和交叉箭头。
- 关联项目共享事实；主项目用于归集。选择多个关联项目时批量保存，不让每次点选都触发网络并关掉下拉。
- 未提交输入在保存失败、刷新、关抽屉、切日期、离开编辑时受保护；新事项不能继承上一个事项草稿。
- 多次点击不重复提交。按钮 loading 保持原文字；首屏加载有占位，后续只做局部忙碌。
- 空态说明原因及下一步；错误与空态区分。不能把加载失败显示成“没有数据”。
- 列表 j/k、Enter、Esc 不能劫持输入框/按钮/弹层；中文组合输入不提交；长列表上下方向键保留滚动。
- 点击行内按钮不能同时打开详情；动作后焦点保持在相关列表。可交互元素键盘可达并有可见 focus。
- 项目和日期只是组织事实的方式，不强迫用户补全字段；不能凭数据替用户写“你答应了某人”。

## 3. UI 标准

使用 `styles/main.css` 中的设计令牌，沿用紧凑浅色工作界面。信息价值优先于装饰。

| 项 | 标准 |
|---|---|
| 布局 | 桌面 Sidebar 208px，内容最大 1200px；窄桌面折行，无横向滚动；760px 以下改顶部导航，900px 以下事项标题/动作分行 |
| 事项行 | 52–68px，最多两行事实，高频动作常驻；标题过长省略并可进入详情 |
| 区块 | 标题、分隔线、列表；不把每条事项包成大卡片 |
| 详情 | Drawer 520–560px；标题、当前状态/下一步、基本归属；主操作留在底部 |
| 圆角/阴影 | 事项行与区块不加圆角/外阴影；弹层允许；选中行可用内侧色条 |
| 颜色 | 中性文字＋少量状态色，不整行染色；焦点与状态不单靠颜色 |
| 主操作 | 页头至多一个主要按钮；其余用次级、文本或上下文操作 |
| 动画 | 只保留简短反馈，支持 reduced-motion，无装饰性入场动画 |

不增加渐变、玻璃效果、Emoji 主图标、KPI 大卡、发光、深色模式或无意义图表。图标使用 Ant Design Icons。帮助文字应解释业务动作，不能暴露实现术语。

## 4. 检查与交付

1. 前端 `npm run build` 必须通过（含 vue-tsc）；后端按变更运行集成回归。数据库测试只连接专用库。
2. 使用真实后端点通受影响流程；检查 loading、空态、错误、长标题、多页数据、弹层、未保存保护与键盘。
3. 检查 1280×800、1440×900、1728×1117 与 1080 宽度；检查 125%/150% 缩放或等效可用宽度，并明确采用哪种方式。截图只能辅助，不能代替交互验证。
4. 正常流程不出现控制台错误、失败请求或后端异常。故障注入产生的预期失败需单独记录。
5. 涉及业务行为写能发现回归的测试，不为小文案/样式或实现细节本身堆测试。
6. `git diff --check` 通过；文档链接有效；规则更新到唯一所属文档。保留用户已有改动。
7. 本项目允许保留丰富测试数据，但放在可识别的独立示例库。保留原有测试记录，不自动清空用户正在体验的数据。

交付前回答：能否快速找到今天的工作？完成任务是否只需一次动作？多项目是否共享同一事实？两天后回来能否恢复上下文？新增交互是否减少了维护步骤？
