# 技术设计

业务含义见[产品与交互](产品与交互.md)，本文件记录实现边界和关键契约。字段完整定义以代码、SQL、Swagger 为准。

## 1. 架构与目录

```text
Vue 3 + TypeScript + Ant Design Vue
  页面 → api/index.ts → api/client.ts → /api
  Vite 开发代理 / Nginx 静态站点与反向代理
Spring Boot 3 / Java 17
  Controller → Service → Mapper / Converter
PostgreSQL 16
```

前端在 `workos-web/src/`：页面在 `pages`，公共组件在 `components`，行为在 `composables`，接口在 `api`，类型在 `types`，设计令牌在 `styles/main.css`。Pinia 已注册但无页面数据 store。

后端在 `workos-server/src/main/java/com/workos/`，按 item、project、today、inbox、worklog、daily、followup、reminder、settings、search 分域。每域沿 controller、service/impl、converter、data/entity、data/mapper、model/request/response/dto 分层。

## 2. 数据模型

初始化执行 [01-init.sql](../deploy/db/01-init.sql)，关联项目增量执行 [02-item-project-links.sql](../deploy/db/02-item-project-links.sql)。没有 Flyway。新库需两份都执行；已有库只执行增量，详见运行手册。

| 表 | 职责和关键字段 |
|---|---|
| project | 项目名称、code、状态 ACTIVE/ARCHIVED、排序和 version |
| project_context | 每项目一份现状，goal/focus/progress_note/blocker/next_action/key_people/key_links/notes_markdown、version |
| item | 主项目 project_id、标题/描述、类型、状态、优先级、计划、截止、等待/跟进、关闭时间、version |
| item_project_link | 关联项目；复合主键 (item_id, project_id)，两侧外键和级联删除，按 project_id 索引 |
| work_log | 当时的 project_id、item_id、work_date、occurred_at、content。人工记录，不含 source |
| item_activity | 系统事件、前后状态、备注、发生时间，用于审计，不作为日报工作内容 |
| daily | 每日期一份正文与生成快照、version |
| reminder | PENDING/DISMISSED/CANCELLED，没有 FIRED；时间到不等于已送达 |
| settings | 单行设置，时区和日界线事实源 |
| account | 单用户身份结构预留，尚未接入鉴权 |

Item 没有父子任务或每关联项目一份状态。关联项目增加不修改旧 project_id，不迁移旧事项的归属。

## 3. 关键事务与数据一致性

- `ItemStateMachine` 与 `ItemTypeCapability` 是合法流转来源，装配 `allowedTransitions`。界面只使用该集合显示可执行目标。
- 记录到 TODAY 在同一事务写入 TODO 与业务日计划。项目内记录可传主项目 ID，仍只要求标题。
- 状态更新、退出等待清字段、活动记录属于同一事务。跟进的记录和日期清理必须一起提交。
- 主项目、关联项目及事项版本一起更新。校验所有项目存在、去重、排除主项目、最多 20 个；有关联时必须有主项目。新增关联失败或版本过期，整个更新回滚。
- `relatedProjectIds` 缺省/null 不修改，`[]` 清空。更换主项目会从关联集合移除新主项目。
- 项目筛选用主项目条件 OR 关联表 EXISTS，避免 JOIN 放大分页；项目统计用主归属与关联归属 UNION 后聚合。关联展示批量查询，避免逐行 N+1。
- 工作记录保存当时主项目，改变事项主项目不重写历史记录。日报按记录的 project_id 分组；关联项目不复制记录。
- Today 先按 SQL 查询事实，再按 ID 顺序去重；候选有 5 条上限。具体归属顺序见产品文档。
- 项目现状响应携带 version，保存校验编辑开始时版本；首次空现状版本为 0，首次保存升为 1，避免陈旧空白页覆盖已保存内容。
- Daily 生成只写 generated_content，返回新 version；apply 才写 content，并校验 version。

## 4. 接口共同约定

根路径 `/api`。统一 `BaseResponse<T>`：`code` 为整数，0 成功；业务失败通常仍是 HTTP 200，以 code/message 判断。分页字段为 `total/pageNo/pageSize/dataList`。

ID 为 Long，序列化成字符串；前端一律 string。数量字段在 API 边界转 number，不能把 ID 转数字。

更新传 version；服务拒绝过期版本，返回冲突。部分旧接口仍允许省略 version，前端应始终传已有版本。空值默认“不修改”；清空项目/截止/跟进使用 `clearProject / clearDueAt / clearNextFollowUp`，关联项目用空数组。

状态只走 transitions，属性更新不能传 status。计划通过 plan/unplan，业务日期由服务端计算。错误显示具体原因，失败保留输入并允许重试。

### 接口索引

| 模块 | 接口 |
|---|---|
| Today | `GET /today`；`POST /today/plan/reorder` |
| Inbox | `GET /inbox`；`POST /inbox/accept-all`（可指定 itemIds） |
| Item | `GET/POST /items`；`POST /items/quick-capture`；`GET/PUT/DELETE /items/{id}` |
| 状态/跟进 | `POST /items/{id}/transitions`；`POST /items/{id}/follow-up-actions` |
| 计划/历史 | `POST/DELETE /items/{id}/plan`；`GET /items/{id}/activities` |
| Project | `GET/POST /projects`；`GET/PUT /projects/{id}`；`POST /projects/{id}/archive`、`/restore` |
| 现状 | `GET/PUT /projects/{id}/context` |
| WorkLog | `GET/POST /work-logs`，按 itemId/projectId/workDate 查询 |
| Daily | `GET /dailies?weekStart=`；`GET/PUT /dailies/{date}`；`POST /dailies/{date}/generate`、`/apply-generated` |
| Reminder | `POST /reminders`；`PUT /reminders/{id}`；`POST /reminders/{id}/dismiss`；`GET /reminders/pending` |
| 其他 | `GET /search`；`GET /follow-ups`；`GET/PUT /settings` |

新增/更新事项接受 `relatedProjectIds: string[]`；所有事项响应增加 `relatedProjects: [{projectId, projectName, itemId}]`。原 projectId/projectName 表示主项目。`GET /items?projectId=` 同时查主归属和关联。

## 5. 时间与乐观锁

- 时间点存 TIMESTAMPTZ，API 用 ISO Instant；日期存 DATE，传 `YYYY-MM-DD`。显示使用 dayjs，不用截字符串伪造日期。
- `settings.timezone`＋`TimeZoneHolder` 决定业务今天及日边界；日界固定 0 点，不能让不同页面各算一次业务今天。
- `waitingExpectedAt` 是对方预计时间，`nextFollowUpAt` 是自己推动时间，`dueAt` 是截止，`plannedDate` 是计划。四者不能互相覆盖。
- MyBatis-Plus 更新默认忽略 null，显式清空需 UpdateWrapper。检查受影响行数，否则版本冲突可能被当作成功。
- 版本在前端编辑开始时保留，不应在用户仍编辑时用后台刷新出来的新版本代替，造成陈旧内容覆盖新内容。

## 6. 前端行为分工

| 模块 | 单一职责 |
|---|---|
| QuickCapture | 输入/目标/可选项目上下文/提交；处理输入法、忙碌状态、失败保留 |
| ItemCard | 展示服务端事实并发出 action；无后端请求、无状态机副本 |
| ItemDrawer | 深度编辑、记录、历史；保留草稿、切事项重置、关闭保护 |
| ItemStateFlow | 展示当前状态到 allowedTransitions 的局部图，转发动作，无业务规则副本 |
| useListActions | 行内忙碌、写后重读、撤销、焦点和 j/k 键盘行为 |
| useCaptureRefresh | 记录成功后通知当前视图重读；不保存第二份业务状态 |
| API 层 | HTTP、统一解包、失败、数值归一化；页面不能直接使用 axios |

写操作后重新 GET，不做乐观模拟。首屏 loading 可整体占位，已呈现列表不因刷新清空。多次查询防止较旧响应覆盖当前筛选。属性即时保存，关联项目一次批量保存，文本草稿在离开时受保护。

Vite 默认代理 8080，可用 `WORKOS_API_TARGET` 指向独立验收后端；`VITE_WORKOS_DEMO=true` 仅用于显示示例工作区标识，不是数据隔离措施。真正隔离依靠独立后端的 DB_NAME。


## 7. macOS 桌面运行方式

`workos-desktop/` 使用 Tauri 2 原生窗口、应用菜单、状态栏和单实例插件，复用 Vue 页面和全部 Java 业务 Service。桌面构建将静态资源嵌入 Java 包，并用 `jlink` 打包 Java 17 运行时。运行不依赖系统 Java、Node、Maven、Docker 或 PostgreSQL。首期仅 macOS，构建架构跟随当前机器。

启动链路：原生进程 → 内置 Java 子进程 → SQLite 初始化/版本检查 → 当日备份 → `ready.json` → 打开本地页面。Java 监听 `127.0.0.1` 的随机端口，避免与 Web 端口冲突。每次启动生成随机会话密钥，经连接入口交换 HttpOnly/SameSite Cookie；校验 Host、Origin 和会话，前端不获得 Tauri 文件或命令权限。桌面仍含内部服务，但由应用管理生命周期。

- 关闭窗口隐藏；Dock 或状态栏重新显示。退出应用同时停止 Java；父进程异常消失时 Java 自行退出。Java 意外退出最多自动重启 3 次；已保存数据保留，未提交草稿不承诺跨进程故障恢复。
- 桌面 Today 在重新聚焦及可见时每分钟重读服务端事实，处理唤醒/跨日；不刷新未提交输入和打开的抽屉。
- 数据在 `~/Library/Application Support/com.workos.desktop/`，应用升级不覆盖此目录。文件锁阻止两个后端同时打开同一工作区。`WORKOS_DATA_DIR` 可指定独立验收目录。
- `application-desktop.yml` 与 `com.workos.desktop` 仅在 desktop profile 生效。SQLite 开启 WAL、外键、10 秒忙等待，连接池单连接使写事务顺序执行。`PRAGMA user_version=1` 管理结构版本；新版结构拒绝由旧应用打开。
- SQLite 时间点存 epoch 毫秒，日期存 ISO 文本；专用 MyBatis TypeHandler 保持 API 的 Instant/LocalDate 契约。桌面 Mapper 位于 `resources/desktop/mapper`，替换 PostgreSQL 的 DISTINCT ON / ILIKE / 日期差语法；分页使用 SQLite 方言。未来结构升级须追加版本迁移，禁止重建工作库。
- `DesktopStorage` 提供 `/api/desktop/storage`、`backup`、`import`、`restore`。备份通过 SQLite `VACUUM INTO` 生成一致性快照，再原子改名。每日首次运行及跨日检查自动备份，保留 14 份；手动和覆盖前备份保留。
- 迁移仅接受当前本机默认 compose 工作库/示例库。PostgreSQL 用只读可重复读事务；复制 ID、关联、时间、正文、设置等 10 张表到空 SQLite 事务（仅浏览日报自动生成的未编辑模板不阻止导入），核对行数与外键后提交。源库不修改，之后两端不自动同步。
- 恢复仅接受备份目录内的正常文件，校验完整性和结构版本；先备份当前数据，再在事务内替换全部表，失败回滚。导入/恢复后重载业务时区设置。

实现选型依据：[Tauri 生命周期与侧车文档](https://v2.tauri.app/develop/sidecar/)、[官方单实例插件](https://v2.tauri.app/plugin/single-instance/)、[Xerial SQLite JDBC](https://github.com/xerial/sqlite-jdbc)。使用官方依赖，未复制第三方 Spring 桌面模板；只实现本项目需要的启动就绪、回环会话、进程回收和数据迁移。Tauri 使用 MIT/Apache-2.0，SQLite JDBC 使用 Apache-2.0；内置 Java 的许可证随 runtime/legal 保留，原生与前端依赖声明自动收集到包内 THIRD-PARTY-NOTICES.txt。
