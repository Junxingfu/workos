### 2.4 起前端

前端有独立手册：[前端运维手册.md](前端运维手册.md)（环境、启动、构建、Nginx 部署、故障排查都在那里）。

只要记住一条：**前端必须和后端一起起**。Vite 把 `/api` 代理到 `http://localhost:8080`，只起前端时所有接口都报"无法连接后端服务"。

后端按 `http://localhost:[*]`（任意本地端口）放行 CORS（见 `WebMvcConfig`），但开发期走 Vite 代理，浏览器侧不会触发跨域。

## 3. 配置项

后端全部配置走环境变量，默认值见 `workos-server/src/main/resources/application.yml`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVER_PORT` | 8080 | 服务端口 |
| `DB_HOST` | localhost | 数据库地址 |
| `DB_PORT` | 5432 | 数据库端口 |
| `DB_NAME` | workos | 库名 |
| `DB_USERNAME` | workos | 用户名 |
| `DB_PASSWORD` | workos | 密码 |
| `CORS_ALLOWED_ORIGIN_PATTERNS` | `http://localhost:[*],http://127.0.0.1:[*]` | 允许的前端来源模式（Spring 语法，`[*]` = 任意端口），逗号分隔 |

为什么是"任意本地端口"而不是写死 5173：5173 被占用时 Vite 会自动顺延到 5174/5175，而代理转发会原样带上 `Origin` 头，写死端口会让 POST/PUT/DELETE 全部 403，且只有非 GET 请求会中招（GET 不带 `Origin`），现象极具误导性。详见 [前端运维手册.md §8](前端运维手册.md)。

生产同域反代时不需要 CORS，可用该变量收窄为实际域名。

业务上的"今天"由 `settings.timezone` 决定，不是由 `spring.jackson.time-zone` 决定。改时区请在界面上改，或：

```bash
curl -X PUT http://localhost:8080/api/settings \
  -H 'Content-Type: application/json' \
  -d '{"timezone":"Asia/Shanghai"}'
```

## 4. 日常运维

### 4.1 启动 / 停止

```bash
# 数据库
docker compose up -d          # 启动
docker compose stop           # 停止（保留数据）
docker compose start          # 再启动

# 后端（前台运行，Ctrl+C 停止）
cd workos-server && mvn spring-boot:run

# 后端（后台运行 + 日志落盘）
cd workos-server && nohup mvn spring-boot:run > /tmp/workos-server.log 2>&1 &
tail -f /tmp/workos-server.log
```

**重要**：用 `nohup ... &` 在一次性 shell 会话里启动，进程会随该会话结束被杀掉。要长期驻留请用 `tmux`/`screen`，或打成 jar 后用系统服务托管：

```bash
cd workos-server
mvn -o clean package -DskipTests
java -jar target/workos-server-0.1.0-SNAPSHOT.jar
```

### 4.2 打包

```bash
cd workos-server && mvn -o clean package -DskipTests
```

离线（`-o`）可用，因为 `~/.m2` 依赖齐全。若要引入新依赖，去掉 `-o` 或用国内镜像（见 §6）。

### 4.3 查看日志

```bash
# 后端
tail -100 /tmp/workos-server.log

# 数据库
docker logs --tail 100 workos-postgres
```

### 4.4 备份与恢复

```bash
# 备份（保留最近 14 份）
mkdir -p ~/workos-backup
docker exec workos-postgres pg_dump -U workos workos \
  | gzip > ~/workos-backup/workos_$(date +%F).sql.gz
find ~/workos-backup -name 'workos_*.sql.gz' -mtime +14 -delete

# 恢复
gunzip -c ~/workos-backup/workos_2026-09-24.sql.gz \
  | docker exec -i workos-postgres psql -U workos -d workos
```

### 4.5 重置数据库（会丢数据）

建表脚本只在数据卷为空时执行，所以**改了 `01-init.sql` 必须重建卷**：

```bash
docker compose down -v      # -v 会删除数据卷，不可恢复
docker compose up -d
docker exec workos-postgres psql -U workos -d workos -c '\dt'
```

## 5. 已踩过的坑（重要）

这三条都是实际启动时遇到并修复的，重装环境时如果重现，直接对照。

### 5.1 启动报 `CannotGetJdbcConnectionException`

完整特征：`Failed to obtain JDBC Connection`，栈顶是 `SettingsMapper.selectById`。

根因：数据库没起。`SettingsServiceImpl` 的 `@PostConstruct` 在启动时就要读 `settings` 表，连不上直接启动失败——这是刻意设计的快速失败，不是 bug。

处理：

```bash
docker ps --filter name=workos-postgres            # 容器在不在
docker compose up -d                                # 不在就起
docker exec workos-postgres pg_isready -U workos -d workos
```

### 5.2 接口报 `"code":9999` 且日志出现 `LocalDate not supported`

完整特征：

```
InvalidDefinitionException: Java 8 date/time type `java.time.LocalDate` not supported by default:
add Module "com.fasterxml.jackson.datatype:jackson-datatype-jsr310"
```

根因：`JacksonConfig` 里用了 `builder.modules(...)`，它会**覆盖** Spring Boot 自动注册的 `JavaTimeModule`，于是 `LocalDate` / `LocalDateTime` 全部无法序列化（`Instant` 因为单独注册了序列化器才没暴露）。

修复：必须用 `builder.modulesToInstall(...)` 追加，不能用 `modules(...)` 覆盖。代码里已加注释，改动时不要退回。

### 5.3 字段"清不掉"（不报错，但改不动）

完整特征：退出等待后 `waitingFor` 还在、"移出计划"后 `plannedDate` 还在、清空跟进时间无效、`DONE → TODO` 后 `completedAt` 还在、项目恢复后 `archivedAt` 还在。

根因：MyBatis-Plus 的 `updateById` 默认策略是 `NOT_NULL`——**null 字段不会进 SQL**，所以任何"置空"操作都是静默无效。

修复：所有置空走 `LambdaUpdateWrapper` 显式 `set(字段, null)`，并手动递增 `version`（乐观锁插件不拦截 wrapper 更新）。已在 `ItemServiceImpl.clearItemFields` / `ProjectServiceImpl.clearProjectFields` 中统一封装。

**约束**：以后新增任何"清空某字段"的功能，都必须走这两个方法，不要写 `po.setXxx(null); updateById(po)`。

### 5.4 Flyway 依赖缺失

早期版本引了 `flyway-core`，但本机 `~/.m2` 只有 5.2.1，而 Spring Boot 3.2.4 管理的是 9.22.3，离线构建直接失败。

决策：**移除 Flyway**，改用 docker-compose 挂载 `deploy/db/01-init.sql` 做初始化。代价是脚本只在空卷执行一次，改表结构要么手动执行 SQL，要么重建卷（见 §4.5）。MVP 阶段接受。

## 7. 发布前的验收清单

每次改动后按顺序过一遍：

```bash
BASE=http://localhost:8080
CT='Content-Type: application/json'

# 1. 健康
curl -s $BASE/actuator/health

# 2. 设置（时区是"今天"的真源）
curl -s $BASE/api/settings

# 3. 快速记录 -> Inbox
curl -s -X POST $BASE/api/items/quick-capture -H "$CT" -d '{"content":"验收用：明天跟进供应商接口"}'

# 4. 先都收下
curl -s -X POST $BASE/api/inbox/accept-all -H "$CT" -d '{}'

# 5. 状态机：缺等待对象必须报 3004
curl -s -X POST $BASE/api/items/1/transitions -H "$CT" -d '{"toStatus":"WAITING"}'

# 6. 进入等待（带等待对象 + 过期跟进时间）
curl -s -X POST $BASE/api/items/1/transitions -H "$CT" \
  -d '{"toStatus":"WAITING","waitingFor":"供应商张工","nextFollowUpAt":"2026-09-20T02:00:00Z"}'

# 7. Today：该条应落在 followUp 分区
curl -s $BASE/api/today

# 8. 退出等待：waitingFor / waitingSince / nextFollowUpAt 必须全部消失
curl -s -X POST $BASE/api/items/1/transitions -H "$CT" -d '{"toStatus":"DOING"}'

# 9. 乐观锁：版本传错必须报 1004
curl -s -X PUT $BASE/api/items/1 -H "$CT" -d '{"version":99,"title":"x"}'

# 10. 删除保护：已整理事项必须报 3005
curl -s -X DELETE $BASE/api/items/1
```

判定标准：

| 步骤 | 期望 |
|---|---|
| 1 / 2 / 3 / 4 | `"code":0` |
| 5 | `"code":3004` |
| 6 / 7 / 8 | `"code":0`，且第 8 步响应里不含 `waitingFor`、`waitingSince`、`nextFollowUpAt` |
| 9 | `"code":1004` |
| 10 | `"code":3005` |

## 8. 部署到服务器时的差异

MVP 目前只在本机跑过。上服务器时至少处理：

1. **改密码**：`docker-compose.yml` 里的 `workos/workos` 必须换成强密码，并同步 `DB_PASSWORD` 环境变量。
2. **不要暴露 5432**：把 `ports` 改成 `127.0.0.1:5432:5432`，或直接删掉该行，只让后端容器通过 compose 网络访问。
3. **前端同域**：生产建议用 Nginx 反代，前端静态资源与 `/api` 同域，这样 CORS 不用开。完整配置见 [前端运维手册.md §5](前端运维手册.md)。
4. **时区**：容器 `TZ=UTC` 保持不动（时间点统一存 UTC），业务日按 `settings.timezone` 算。
5. **备份定时**：把 §4.4 的 `pg_dump` 挂到 cron，并确认备份文件落在数据卷之外。
6. **日志外置**：jar 方式的 stdout 交给 systemd/journald；容器方式注意 `docker logs` 的轮转上限。

## 9. 错误码速查

| 码 | 含义 | 常见触发 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 参数错误 | 校验失败、计划日期早于今天 |
| 1002 | 数据不存在 | — |
| 1004 | 版本冲突 | 乐观锁，前端应提示刷新 |
| 2001 / 2004 | 项目不存在 / 名称重复 | — |
| 3001 | 事项不存在 | — |
| 3002 | 非法状态转换 | 如 `INBOX → DOING` |
| 3003 | 类型不支持该状态 | `NOTE → TODO` |
| 3004 | 缺少等待对象 | 进入 WAITING 未传 `waitingFor` |
| 3005 | 已整理不可删除 | 非 INBOX 事项走 DELETE |
| 4003 / 5001 / 6001 | 日报版本冲突 / 提醒不存在 / 未登录 | — |
| 9999 | 系统异常 | 看后端日志 |

> 说明：文档 6 定义的是字符串错误码（`ITEM_NOT_FOUND`），本项目按既有工程风格统一为整数码，含义一一对应，见 `common/enums/ResponseCode.java`。
