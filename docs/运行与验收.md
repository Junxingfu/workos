# 运行与验收

命令从仓库根目录执行，除非明确注明。当前以可信本机 Web 使用为目标。

## 1. 启动与配置

需要 JDK 17、Maven、Node.js/npm、Docker 与 PostgreSQL 16。Maven 自身必须运行在 JDK 17；`mvn -v` 检查，不能只设置 javac。若本机 Maven 启动脚本覆盖 JAVA_HOME，可加 `MAVEN_SKIP_RC=true`。

```bash
docker compose up -d
```

后端终端（workos-server 目录）：

```bash
mvn spring-boot:run
```

前端终端（workos-web 目录）：

```bash
npm ci
npm run dev -- --host 127.0.0.1
```

默认前端 5173、后端 8080、数据库 5432。Swagger：`http://localhost:8080/swagger-ui.html`；健康检查：`http://localhost:8080/actuator/health`。

| 变量 | 默认/用途 |
|---|---|
| DB_HOST / DB_PORT | localhost / 5432 |
| DB_NAME | workos；工作库和示例库必须分别指定 |
| DB_USERNAME / DB_PASSWORD | 本地 compose 示例为 workos/workos |
| SERVER_PORT | 8080 |
| CORS_ALLOWED_ORIGIN_PATTERNS | 本地 localhost/127.0.0.1 任意端口 |
| WORKOS_API_TARGET | Vite 开发代理，默认 http://localhost:8080 |
| VITE_WORKOS_DEMO | true 显示示例工作区标识；只有文字标识，不能代替独立数据库 |

本机 JDK 17 路径（仅本机环境参考）：`/Users/fujunxing/Library/Java/JavaVirtualMachines/azul-17.0.14/Contents/Home`。

## 2. 新库与升级

Docker 空卷初始化会依次执行 01、02 两份挂载 SQL；已有数据卷不会重新运行初始化脚本。

升级现有库先备份，再执行增量：

```bash
docker exec workos-postgres pg_dump -U workos workos > /private/tmp/workos-before-project-links.sql
docker exec -i workos-postgres psql -v ON_ERROR_STOP=1 -U workos -d workos < deploy/db/02-item-project-links.sql
```

`02` 可重复执行，只新增关联表及索引，不重写现有事项。升级后重启后端。需要回退应用时可以保留空闲关联表，不要用删除表或重建卷代替回退。

## 3. 独立示例工作区

当前保留 `workos_usability_20261011`，丰富示例和浏览器体验记录在该库；自动回归另用空测试库，工作库仍为 `workos`。新机器可以改用 `workos_demo`：

```bash
docker exec workos-postgres createdb -U workos workos_demo
docker exec -i workos-postgres psql -v ON_ERROR_STOP=1 -U workos -d workos_demo < deploy/db/01-init.sql
docker exec -i workos-postgres psql -v ON_ERROR_STOP=1 -U workos -d workos_demo < deploy/db/02-item-project-links.sql
docker exec -i workos-postgres psql -v ON_ERROR_STOP=1 -U workos -d workos_demo < deploy/db/demo-data.sql
```

[demo-data.sql](../deploy/db/demo-data.sql) 只接受 `workos_demo* / workos_test* / workos_usability*` 库名；补充项目、不同生命周期事项、跨项目关联、等待/跟进、旧计划、笔记和近一周记录。日期以首次执行时的业务日生成。重复执行只补缺失数据，保留已有状态及用户体验记录，不重置日期。

独立示例后端（workos-server 目录）：

```bash
DB_NAME=workos_usability_20261011 SERVER_PORT=8081 mvn spring-boot:run
```

独立示例前端（workos-web 目录）：

```bash
WORKOS_API_TARGET=http://127.0.0.1:8081 VITE_WORKOS_DEMO=true npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

工作入口仍为 5173，示例入口为 5174。示例必须明确标识，不能把样例伪装成工作数据。此脚本不在 docker-compose 启动时自动执行。

## 5. 构建、部署和运行边界

```bash
# workos-web 目录
npm ci
npm run build
# workos-server 目录
mvn package -DskipTests
java -jar target/workos-server-0.1.0-SNAPSHOT.jar
```

静态文件为 workos-web/dist。Nginx 同域示例：

```nginx
server {
    listen 80;
    root /srv/workos/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ { proxy_pass http://127.0.0.1:8080; }
}
```

当前登录鉴权未实现，配置项不等于权限保护，不能直接暴露公网。共享环境部署需先完成身份验证、限制数据库端口并替换本地示例凭据。上述示例本身不是安全上线方案。

## 6. 备份、恢复与排障

备份：`docker exec workos-postgres pg_dump -U workos workos > workos-backup.sql`。备份应另存到独立存储，目标每日一份、保留 14 份；当前没有自动任务，需运维自行安排。

恢复先建新空库，再将 SQL 导入新库，连接该库检查项目/事项/日报数量及读取结果。确认恢复有效后再切换服务，避免覆盖唯一工作副本。不要把 `docker compose down -v` 当作日常停机，它会删除数据卷；普通停机用 `docker compose stop`。

| 现象 | 检查与处理 |
|---|---|
| Docker 连接失败 | 启动 Docker/Colima，检查 docker ps；勿重建已有卷 |
| Maven release/字节码版本报错 | 检查 mvn -v 与 JAVA_HOME，Maven 必须跑在 JDK 17 |
| 页面接口全部失败 | 检查 8080/8081 健康、DB_NAME 和 Vite WORKOS_API_TARGET；不要盲目切工作库测试 |
| GET 正常而写请求 CORS 失败 | 检查代理及后端本地来源配置；开发代理移除 Origin/Referer 的既有处理应保留 |
| item_project_link 不存在 | 已有库尚未执行 02 增量脚本，执行后重启后端 |
| 清空字段不生效 | MyBatis 默认忽略 null；检查显式 clear 标志和 UpdateWrapper |
| 版本冲突 | 重新获取服务器事实，保留草稿让用户核对；不能去掉 version 校验 |
| 刷新子路由 404 | Nginx 缺少 try_files 回落到 index.html |
| 数据像示例或事项消失 | 核对前端端口、代理目标和后端 DB_NAME，再核对状态/项目筛选 |

运行状态以健康检查和页面实际读取为准。文档中的端口不证明进程当前正在运行。
