# 运行与验收

命令从仓库根目录执行，除非明确注明。日常使用优先 macOS 桌面应用，Web 开发方式仍保留。

## 1. 启动与配置

### macOS 桌面应用（推荐）

构建产物在 `workos-desktop/src-tauri/target/release/bundle/macos/WorkOS.app`，磁盘镜像在同级 `dmg/`。双击应用，或将其放到“应用程序”；日常使用不要求安装 Java、Node、Rust 或 Docker。

- 左侧“数据与备份”可在空工作区导入旧工作库。仅迁移时需要原本机 PostgreSQL 运行；默认来源 `workos`，也可选择原示例库。导入保留原库，之后双方独立，避免继续在两端交替写同一份工作。
- 点击红色关闭按钮隐藏窗口；Dock 或状态栏“打开 WorkOS”恢复。`⌘Q` 或“退出 WorkOS”同时关闭内置服务。双开只显示已有窗口。
- 数据目录：`~/Library/Application Support/com.workos.desktop/`。应用“工作区”菜单可直接打开。`workos.db` 为数据库，`backups/` 为快照，`desktop.log` 为日志。不要在应用运行时直接复制单个数据库文件，使用“立即备份”。
- 每天首次运行及运行期间跨日自动备份，保留最近 14 份；手动和恢复前备份不自动清理。“恢复此备份”会覆盖当前数据，并先保存一份当前副本。
- 电脑真正休眠时应用也暂停；唤醒后继续使用。未提交输入不承诺在应用崩溃后恢复。替换 `.app` 不会删除用户数据。
- 本地产物采用 ad-hoc 本地签名，供当前 Mac 使用；尚未配置 Apple Developer ID 签名、公证和自动更新，不能视为已经完成公开分发。

从源码构建需要 JDK 17、Maven、Node/npm、Rust 和 Xcode Command Line Tools：

```bash
source "$HOME/.cargo/env"  # Rust 未加入 PATH 时
cd workos-desktop
npm ci
npm run build
```

构建钩子 `scripts/build-desktop.py` 自动编译 Vue、打包 desktop Java 资源和生成内置运行时。图标沿用 `workos-web/public/favicon.svg`。开发桌面壳前可先运行该脚本，再在 workos-desktop 执行 `npm run dev`；此模式使用打包前端，修改页面后需要重建资源。

验收时用 `WORKOS_DATA_DIR=/private/tmp/workos-desktop-qa WORKOS_DESKTOP_EXAMPLE=true` 启动应用包中的可执行文件，隔离真实桌面库。SQLite 集成测试自行创建临时目录；原业务回归可指定 desktop profile 和独立目录：

```bash
# workos-server 目录
WORKOS_INTEGRATION_TEST=true WORKOS_DATA_DIR=/private/tmp/workos-sqlite-tests mvn test -Dspring.profiles.active=desktop
```

### Web 服务启动（开发或继续使用 PostgreSQL）

从仓库根目录运行，需要 Python 3 和下文列出的开发环境：

```bash
# 使用 Colima 且尚未运行时，先执行 colima start；Docker Desktop 则先打开应用
./scripts/workos start
./scripts/workos status
./scripts/workos logs
./scripts/workos stop
# 修改后端后，重新打包并启动
./scripts/workos restart
```

工作入口 `http://127.0.0.1:5173/`。`start` 会检查端口、Docker 和库结构，启动已有 PostgreSQL 容器，使用 JDK 17 打包后端并让 macOS launchd 托管 Java/Vite。已运行的托管进程不会重复启动；端口被 IDE/手动进程占用时明确报错，不杀其他进程。前端代码自动刷新，后端代码改变需 restart。第一次缺少前端依赖会 npm ci；Maven 缺少缓存依赖时需要网络。

- 关闭启动终端或聊天后仍继续运行，进程意外退出约 10 秒内重新尝试启动。
- 只在当前 macOS 登录会话注册，不安装登录项；退出登录或重启电脑后，先启动 Docker/Colima，再执行 start。
- 锁屏本身不等于休眠；真正休眠或合盖时，本机服务暂停，无法保证继续访问。唤醒后用 status 检查；若 Docker 退出，先恢复 Docker，再 start。脚本不更改电源设置。
- `stop` 仅卸载本仓库对应的前后端服务，保留数据库容器及全部数据。
- `.runtime/work/` 保存进程定义和 server.log/web.log/build.log，已忽略 Git；status 同时检查进程及 HTTP/API，不把进程存在当作健康。
- 示例库启动为 `./scripts/workos start demo`，查看/停止同样追加 demo；它使用 5174/8081 和 `workos_usability_20261011`，库需按第 3 节提前创建，脚本不导入或覆盖示例数据。
- 脚本使用本地 compose 的默认数据库账号和端口，不用于远端或自定义数据库部署。数据库结构由后端 Flyway 识别和升级，升级前按第 2 节备份。

## 2. 新库与升级

结构由 Flyway 在应用启动时管理，唯一 SQL 位于 `workos-server/src/main/resources/db/migration/{postgresql,sqlite}`。Docker 只创建数据库，不挂载建表 SQL。

- 新库自动执行全部迁移；PostgreSQL 当前 V4，SQLite 当前 V3。
- 无 Flyway 历史表的已知旧库，先检查必要表和版本组合，再建立基线并执行增量；损坏/未知结构拒绝接管。不要手工设置 baseline 来绕过错误。
- SQLite 接管前保存 `backups/before-flyway-*.db`；后续升级前保存 `before-migration-*.db`。新结构 `PRAGMA user_version=3`，旧应用不能继续打开。
- PostgreSQL 升级前备份：`docker exec workos-postgres pg_dump -U workos workos > workos-before-upgrade.sql`，然后启动新版后端。不要删卷或重建库。
- 迁移历史可查询 `flyway_schema_history`；SQLite 字段注释可查询 `schema_comment`。已发布的迁移不可修改，追加新版本；不要用 repair 自动掩盖校验和不一致。
- 恢复旧 SQLite v1/v2 备份仍使用当前表结构，新增表为空、缺少 version 的旧记录使用默认值；保留当前 Flyway 历史。降级应用应恢复对应升级前备份到独立目录，不让旧版直接打开新版工作库。

## 6. 备份、恢复与排障

备份：`docker exec workos-postgres pg_dump -U workos workos > workos-backup.sql`。备份应另存到独立存储，目标每日一份、保留 14 份；当前没有自动任务，需运维自行安排。

恢复先建新空库，再将 SQL 导入新库，连接该库检查项目/事项/日报数量及读取结果。确认恢复有效后再切换服务，避免覆盖唯一工作副本。不要把 `docker compose down -v` 当作日常停机，它会删除数据卷；普通停机用 `docker compose stop`。

| 现象 | 检查与处理 |
|---|---|
| Docker 连接失败 | 启动 Docker/Colima，检查 docker ps；勿重建已有卷 |
| Maven release/字节码版本报错 | 检查 mvn -v 与 JAVA_HOME，Maven 必须跑在 JDK 17 |
| 页面接口全部失败 | 检查 8080/8081 健康、DB_NAME 和 Vite WORKOS_API_TARGET；不要盲目切工作库测试 |
| GET 正常而写请求 CORS 失败 | 检查代理及后端本地来源配置；开发代理移除 Origin/Referer 的既有处理应保留 |
| 结构缺失或迁移失败 | 检查 Flyway 日志、历史表和升级前备份；不要手工补建表绕过迁移 |
| 清空字段不生效 | MyBatis 默认忽略 null；检查显式 clear 标志和 UpdateWrapper |
| 版本冲突 | 重新获取服务器事实，保留草稿让用户核对；不能去掉 version 校验 |
| 刷新子路由 404 | Nginx 缺少 try_files 回落到 index.html |
| 数据像示例或事项消失 | 核对前端端口、代理目标和后端 DB_NAME，再核对状态/项目筛选 |

运行状态以健康检查和页面实际读取为准。文档中的端口不证明进程当前正在运行。
